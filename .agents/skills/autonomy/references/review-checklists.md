# 实施与验收清单
模式：READ-DO | 派发/验收逐条读

## 通用四轴

1. 目标与完整性：逐项对照冻结范围、交付物和验收标准。
2. 真实性与安全：结论有来源和实测证据，遵守本任务写入、发布和授权红线。
3. 结构与简洁度：保留交付所需结构，去掉重复内容和无用层次。
4. 表达与一致性：核对术语、数字、格式及跨产物对应关系。
审写分离，语义审查优先安排异族跨模型，遵守 AGENTS.md 授权与角色边界。验收记录产物版本及稳定清单条目。重申：结论必有实测证据。

## 代码

- 多文件改造前先跑通最小端到端切片校准接口。
- 先红后绿，核心路径至少一条非 Mock 实测断言。并行前冻结共享接口契约。
- 核对测试与冻结验收标准，禁止弱化或篡改断言。附实际输出、差异摘要和 `git status`。
- 禁可信路径冗余判空、空 catch 及无调用方抽象。对照实际入口及历史数据验证。

## 文案 / PPT

- 派发前有同体裁近邻样段时先试写最难一段校准。
- 长文或超过 5 页的 PPT 先落盘大纲，经确认后成稿。非 git 目录改前 `cp -a` 快照。
- 复用 `pptx` Skill 渲染并逐页看图，按冻结版式硬限检查字号、边距、溢出与重叠，图表与正文同源。
- 文案套话初筛（2026-11，`weak-alone`）：标记空泛总结、模板式转折与无证据评价，结合上下文裁决。事实零新增，按用户真文样本定位表达锚点；无样本严格 `cleanup-only`，只清理表达，禁加戏。
- 复验无重复句、无主语缺失，禁为简略删限定。

## 科研

- 派发前锁定核心假设与 Claim 边界。
- 长实验先以小样 Smoke Test 验证链路，再独立启动全量后台跑批；跑批由执行端负责。固定随机种子及数据、代码、依赖版本。
- 图、表、正文数值从同一 `metrics.json` 生成，禁手抄；保留配置与结果快照供复验。
- 文献用 `bibguard` 或 DOI 实测核验并核对元数据，未核验标 `[UNVERIFIED]`，禁入终稿。
