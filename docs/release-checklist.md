- [ ] 单次派单，核对唯一回执、Task/Worker 事件、`worker_done` 终态和资源回收。复验 `--keep-open` 终端能否跨创建者存活，并确认手工关闭。
- [ ] 复验已知请求重放、真实断连后的 pending、回执丢失及恢复。先查原生请求记录，再验证重试未重复派单。

## 升级试跑与回滚检查

1. 记录 `<旧技能目录>`、`<旧状态目录>` 和客户端入口。保留旧入口直到存量任务结束。
2. 用独立 Orca Run、新账本和隔离工作区试跑 Codex 派单、用量查询与六行交接，执行相关手工回归。
3. 验收后切换客户端入口，停止旧入口接收新任务。经操作者确认，把旧技能和状态原样归档到 `<归档目录>`，记录恢复路径。
4. 回滚时停止 Conflux 新派单，由原 owner 收尾已启动的 Orca Run。恢复归档中的旧技能、旧状态和客户端入口，验证旧路径可运行。Conflux 账本保留供审计。
